# 样式组件与页面模板

## 1. 生成页面的组件原则

- 售前材料优先使用“结构化组件”表达，不使用大段平铺文字。
- 每页至少包含：标题、核心判断、主体组件、来源/注释或下一步动作。
- 产品、权益、服务流程、案例页必须保留可追溯的产品名、次数、等待期、服务范围和适用人群。
- HTML/PPT 输出时默认 16:9，推荐 1280x720。

## 2. 模板组件库

### 2.1 客户方案封面

用途：客户定制方案、行业解决方案、产品交流材料。

结构：

- 左上或右上：平安健康/平安好医生标识。
- 中左：方案标题。
- 标题下：客户行业、项目名、版本或日期。
- 右侧/底部：城市、建筑、家庭、医生或硬件场景图。
- 底部：公司名或保密提示。

适用来源：PRESALE001、PRESALE006、PRESALE007、PRESALE008、PRESALE010。

### 2.2 目录/章节页

用途：长材料章节分隔。

结构：

- `CONTENT/目录` 或 `目录CONTENTS`。
- 3-4 个章节，中文为主，可带“第一部分/第二部分”。
- 当前章节用平安橙，未展开章节用灰色。
- 右侧可保留橙色竖条或浅灰点阵。

适用来源：PRESALE006、PRESALE007、PRESALE008、PRESALE010。

### 2.3 行业痛点页

用途：解释客户为什么需要方案。

结构：

- 顶部一句判断。
- 主体 3-4 个痛点卡片，每个卡片包含痛点标题、表现、后果。
- 可加入政策/趋势/市场数据时间线。
- 底部给出“方案切入点”。

适配场景：

- 养老：老人更多、老去更快、养老金更少、赡养更难。
- 企业：寻医难、会诊难、诊后无追踪、过度诊疗。
- 地产：硬件内卷、缺服务营销元素、物业缺收入。
- 运营商：用户留存、权益感知、号卡附加值。

### 2.4 能力全景页

用途：展示平安健康综合能力。

结构：

- 中央：核心价值主张或平台能力。
- 四周：家医、专医、名医、就医、健康管理、商城、O2O、养老管家。
- 底部：资源背书，例如医院、医生、名医、服务城市、企业客户。
- 右侧：2-3 个关键数字或认证。

适用来源：PRESALE001、PRESALE002、PRESALE008、PRESALE010。

### 2.5 三档产品卡

用途：会员、权益包、月卡/年卡等分层产品。

结构：

- 3 列或 4 列卡片。
- 顶部：档位名称和价格。
- 中部：共同权益。
- 下部：差异化权益和适用人群。
- 右下/底部：注释和服务限制。

适用来源：

- PRESALE003：个人会员、家庭会员、尊享会员。
- PRESALE010：在线咨询包、就医 VIP 银/金/钻卡。
- PRESALE002：基础版、家庭版、舒享版、保险+。

### 2.6 权益明细表

用途：详细列出服务权益、次数、价格、等待期和口径。

结构：

- 表头平安橙或浅橙。
- 左侧固定产品/服务分类。
- 中间列为不同档位或套餐。
- 关键差异用浅橙底。
- 服务限制和注释放在表格下方。

适配内容：服务次数、门诊预约、住院安排、陪诊、名医视频、心理咨询、体检、洁牙、快检、硬件开卡礼。

### 2.7 履约流程页

用途：证明方案能被用户实际使用。

结构：

- 横向流程：购买/激活 -> 进入入口 -> 选择权益 -> 使用服务 -> 查询记录。
- 下方配手机截图 3-5 张。
- 每张截图上方放编号和动作标签。
- 底部保留“以实际线上展示为准”等提示。

适用来源：PRESALE003、PRESALE004、PRESALE007、PRESALE010。

### 2.8 服务闭环页

用途：表达健康管理或硬件数据如何转成服务效果。

结构：

- 横向五步：监测 -> 建档 -> 评估 -> 干预 -> 改善。
- 每步下方放数据、工具或服务动作。
- 右侧可放硬件图或医生/管家图。
- 底部说明主动服务、随访和线下协助。

适用来源：PRESALE004、PRESALE006、PRESALE009、PRESALE010。

### 2.9 案例证明页

用途：展示客户/行业落地效果。

结构：

- 左侧：合作背景。
- 中部：服务方案或流程。
- 右侧：效果指标或客户反馈。
- 可配客户 App 页面、设备图、城市/社区照片。
- 若涉及客户名或品牌标识，外发前必须确认授权。

适用案例：

- 中国移动全球通健康权益。
- 华为腕部血压手表+家庭医生。
- 招商成都业主权益。
- 天保基建社区健康小屋。
- 银行 App 医养服务嵌入。

### 2.10 FAQ/附录页

用途：处理实施细节和客户疑问。

结构：

- 左侧问题分类，右侧问题和答案。
- 可用表格，不做问答长文。
- 对增减员、权益选择窗口期、撤销重选、等待期、服务范围做明确说明。

适用来源：PRESALE003、PRESALE001。

### 2.11 企业健康报告页

用途：面向企业 HR、工会、行政、员工关怀团队的健康数据复盘、风险解释、服务承接和年度配置建议。

结构：

- 顶部：页标题 + 一句自然的核心判断，不写“领导可读结论”“本页回答什么问题”。
- 主体：根据页面焦点选择指标卡、趋势图、占比条、双端验证、风险刻度、矩阵、流程或照片证据。
- 中下部：解释造成异常的业务/人群/行为原因，以及如果不处理会演化成什么费用、就医、体验或组织风险。
- 底部：本页结论 + 数据口径注释。注释用 `*` 开头，医疗名词或专业名词必须解释。
- 素材：优先使用真实到企活动、医生沟通、体检/医务室、App 服务入口、报告解读现场等页面相关素材；不得用占位图填空。

适配组件：

- 年度综述：`pa-health-metric-grid` + `pa-health-flow` + `pa-health-insight-grid`。
- 人群结构：年龄金字塔/分布图 + 重点名单 chips + 结构判断卡。
- 体检异常：`pa-health-bar-panel` + 风险主线矩阵。
- 心脑血管：`pa-health-dual-proof` + `pa-health-gauge` + 真实医生/服务证据。
- 服务落地：活动照片拼贴 + 满意度/感知提升卡 + 场景价值结论。
- 下一年度配置：服务包矩阵 + 时间线/路径图 + 配置逻辑说明。

## 4. 页面生成优先级

当用户要求生成售前方案时：

1. 先识别客户类型：企业、运营商、地产/物业、养老/政企、硬件、健康管理。
2. 再选择对应结构：参考 `05_产品场景与客户方案映射.md`。
3. 从 `curated_assets.csv` 中查找匹配场景素材。
4. 使用本文件组件生成页面，不足处再回到 `asset_manifest.csv` 和页面渲染图。
5. 输出前检查：产品权益是否完整、注释是否保留、客户案例是否有来源。
