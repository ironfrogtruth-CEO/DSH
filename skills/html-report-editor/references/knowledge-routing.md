# 完整知识库调用路由

## 1. 原则

`html编辑器skill` 有两种知识模式：

1. **完整知识模式**：存在外部 `知识库/` 时启用，作为事实真相层。
2. **便携回退模式**：只有 `resources/knowledge/presale` 时启用，只能支撑售前结构与视觉，不可冒充完整业务知识。

完整知识模式优先级高于 skill 内置精简包。

## 2. 完整知识模式定位顺序

依次寻找：

1. 用户显式提供的 `知识库/` 路径。
2. skill 同级目录的 `知识库/`。
3. 当前工作目录的 `知识库/`。
4. 本机 fallback：`../知识库`。

一旦找到完整知识库，先读：

```text
00_总索引/知识调用架构.md
00_总索引/分类目录索引.md
00_总索引/实体索引.csv
00_总索引/关系索引.csv
00_总索引/知识库文件清单.csv
00_总索引/检索与引用规范.md
```

## 3. 标准调用链

```text
用户需求
-> 判断任务类型
-> 在实体索引中定位服务 / 风险 / 流程 / 场景
-> 在关系索引中补齐相邻节点
-> 进入对应 Wiki 正文读取完整结论
-> 回到来源追溯层锁定 source refs
-> 再写逐页稿和 HTML
```

## 4. 页面规划必须携带的知识字段

逐页稿中至少保留：

```json
{
  "knowledge_mode": "full | portable_fallback",
  "entity_refs": [],
  "relation_refs": [],
  "wiki_sources": [],
  "source_refs": [],
  "truth_status": "verified | needs_review | portable_only"
}
```

## 5. 真源锁定规则

- 业务结论优先落到 Wiki 文件，再追溯到 `ROOT / REPORT / DEPT / PRESALE / NEWMAT`。
- 价格、医学口径、权益次数、等待期、服务范围等易变事实，必须写 `needs_review` 或附原始来源。
- 若只有便携回退模式：
  - 可以写页面结构、视觉风格、通用售前叙事；
  - 不得把精简包当作完整业务事实库；
  - 不得声称已完成完整来源校验。
