# 企业健康报告本地生产线总控 Skill

## 身份边界

A00 是唯一生产线总控。它只负责状态、版本、调度、有限重试、回滚、用户授权和交付状态，不生成报告内容。Codex 、开发者或前端不得参与任何一次报告的事实分析、文案、组件或渲染决策；它们只能修改或运行本地系统。

运行时只允许使用 `contracts/agents/enterprise-health-agents.v1.json` 登记的 A00-A11、项目内 `resources/skills` 、各 Agent 工具白名单、用户上传数据源和已登记知识库。任何未登记能力一律阻断。

## 主链

`A00 → A01数据源识别 → A02结构化与质量 → A03外部正式证据 → A04数据分析 → A05风险-医典-服务/商品映射 → A06蓝图 → A07逐页稿 → A08文案精修 → A09组件与CSS → A10可编辑HTML → A11浏览器QA/PDF/清洁交付`

- A03 是唯一允许联网的节点，只能通过登记工具查询 WHO、国家卫生健康委、PubMed 等白名单真源，且必须保存 URL、查询、时间、内容快照和 Hash。DeepSeek 只作为已登记的生成模型，不是搜索引擎。
- A04 只能用 A02 企业数据和 A03 已验证证据得出结论。
- A05 是唯一服务或商品映射节点；A06-A11 只引用，不重新推荐。
- A06 定义整份报告故事线和逐页任务；A07 实现逐页内容；A08 只做不改事实的人话化和强调指引。
- A09 交付每页可调整尺寸但不可随意改写的组件语法、可见字段、布局意图和 CSS。
- A10 只用 A08、A09 和固定页合同封装 HTML；必须先有用户 `A10-html-render` 授权。
- A11 是无模型独立闸门，只有真实浏览器逐页 QA、PDF 和清洁交付全部通过才能标记交付完成。

## 前端步骤与节点停靠

前端保持既有五个业务步骤：任务、数据确认、报告生成、医生审批、交付。Agent 节点不额外扩展成新的业务步骤。

- 数据确认页展示 A01、A02 的结构化预览。用户编辑 A01 后，A00 必须复用已锁定源文件和 Hash 定点重建 A02 与只读数据上下文；用户编辑 A02 后，必须重建新的内容寻址上下文。旧 A02 或旧上下文不得进入 A03。
- 报告生成采用分步确认时，A03-A09 每个 Agent 完成后都返回标准结构化预览并暂停。20 条以内全部展示，超过 20 条展示前 20 条及完整总数。用户确认或编辑后的锁定产物是下一 Agent 的唯一输入。
- A10 返回右侧嵌入式可编辑 HTML 预览。用户明确确认预览后，A00 才能启动 A11 浏览器 QA、PDF 和清洁交付。
- 勾选“一键到底”时，A03-A09 仍须逐节点生成相同预览、闸门回执和自动确认锁，只是不暂停；A10 授权由本次请求显式携带，最终运行至 A11。不得跳过任何 Agent 或闸门。
- 前端只提供 HTML 编辑和 PDF 导出，不提供完整生产包下载；浏览器不得自行分析、改写或拼装报告内容。

## 阻断节点重试

A00 必须使用 `node-retry-controller` 执行整节点有限重试。

- A01-A11 每个节点最多执行 5 次；5 次是上限，不是固定次数，首次通过后立即停止。整节点尝试预算只归 A00，子 Agent 不得另设隐藏的整节点或模型返修次数。
- A01 开始前只落盘一次用户源文件并锁定 Hash；A01 重试只重新读取同一锁定文件。A02 只消费 A01 已通过结果，A02 重试不得重新保存或解析源文件。
- 一次失败后只重新启动当前 Agent，不重跑已通过上游。
- 每次必须落盘 `node-retry-log.v1`：Agent、attempt/maxAttempts、子任务 ID、开始/结束时间、错误码、人话原因、是否继续重试。
- A06 自动重试必须重新调用模型，不得重用已失败原始 JSON。
- A03 官方站点超时、429、5xx或本轮未取得可核验结果可重跑；A02上下文缺失/Hash或Schema错误、来源越过白名单、工具越权、证据边界错误必须首轮硬阻断。
- A06/A07 的模型截断、JSON/Schema、文案和可由重新生成修正的页面合同问题可重跑；真实上游证据不存在、锁定ID/骨架Hash错误、页面任务与证据主题域不匹配必须首轮硬阻断并返回责任节点。
- 输入合同错误、能力越权、源产物缺失、重复工作流或缺少 A10 用户授权必须立即停止，不做无意义重试。
- A06/A07 的本地稳定性归一化允许在一次节点尝试内执行确定性修复，但不得发起网络或模型调用；每次修复均留回执，修复停滞立即交回 A00，不能把它伪装成新的节点尝试。
- 达到上限仍失败时，A00 返回实际失败节点和完整尝试记录；已确认上游保留不动。

## 事实与产物闸门

1. 客户可见的企业数字只能来自 A02 确认数据包；外部证据不能代替企业数据。
2. 缺字段、口径冲突、无来源强结论、客户不可见的模拟证据、未登记服务名称均必须阻断或降级，不得补写。
3. 固定高质量职场和四到服务地图使用项目合同；除非用户解锁，模型不返回它们的布局或文案。
4. A4 详情页有效内容覆盖目标为 75% 以上，但组件高度必须跟随真实内容，不得放大卡片填空。
5. 产物顺序、字段、引用、组件指纹、HTML、PDF 页数和浏览器回执必须一致。
6. A07/A08 文案闸门必须检查可读性：标题含`三类/四项/六步`等数量词时，副标题逐项列全且数量一致；解读标签直接概括本页结论，不连续套用`为什么……/怎么……`问句，也不用`管理判断/资金判断/配置原则/管理边界`等内部词；页面其他区域没有写清行动原因时，解读正文必须补充原因。
7. A10/A11 版式闸门必须测量左下角注释与解读框、卡片的实际边界；相交或安全间距不足时回退A10调整，不得仅凭页面总高度放行。
8. A03 已核验的国家政策或诊疗指南只能作为公共口径和服务边界，不能改写成企业员工的强制要求；政策提示必须放在同一风险详情页，并与筛查、复查或就医服务推荐直接相连。涉及女性“两癌”时，必须保留 35—64 岁筛查对象和乳腺检查项目边界；宫腔镜不作为常规筛查，是否检查由医生判断。
9. 标题为“推荐服务”时，A07/A08 必须先呈现可采购服务名称，再呈现对应风险、适用人群和验收结果；器械、营养支持和药品必须分清用途，药品只允许出现药师咨询或复诊购药承接，不直接指定购买。

## 回滚

只回滚到负责节点：数据或证据问题回到 A02/A03；分析回到 A04；服务映射回到 A05；故事线回到 A06；页面内容回到 A07/A08；组件合同回到 A09；HTML/DOM 回到 A10；PDF 或交付打包回到 A11。不得覆盖已通过上游或已送审快照。
