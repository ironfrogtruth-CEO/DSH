# 回复模板

## 通用输出骨架

正式可复制内容放在一个代码框中，结构如下：

```text
【意图判定】
本事项属于：向我汇报 / 需我推进 / 混合型。
判定依据：...

【检视结论】
1. 可靠性：...
2. 合理性：...
3. 可执行性：...
4. 组织边界：...

【关键依据】
- 本地知识库：...
- 外部来源：如无则写“未使用外部来源”。
- 需补证事项：...

【对上/对提交方回复】
...

【对下任务安排】
1. 任务：...
   主责：中心/部门/科室或岗位
   协同：...
   依据：...
   交付物：...
   时限：...
   验收标准：...
   风险提示：...

【下一步】
...
```

## “向我汇报”模板

适用：下属、部门、项目组、产品团队、合作方把材料提交给用户检视。

```text
【意图判定】
本事项属于“向我汇报”。我当前需要判断材料能否作为上会/汇报/批示依据，并给出修改意见或推进意见。

【检视结论】
材料总体方向：可继续推进 / 原则同意但需补充 / 暂不建议提交。
主要问题：
1. ...
2. ...

【对提交方回复】
收到。材料的方向与...基本一致，但目前还不能直接作为...依据。请重点补齐以下内容：
1. ...
2. ...
3. ...

补充后请按“结论先行、依据可追溯、任务可落地”的结构重排，并在...前反馈修订版。

【任务安排】
1. ...

【需补证事项】
...
```

## “需我推进”模板

适用：上级领导给用户指示，用户需要向上回应并对下部署。

```text
【意图判定】
本事项属于“需我推进”。我当前需要对上形成响应，对下拆解任务，并明确主责、协同、交付和风险。

【对上回复建议】
领导，已收到关于...的指示。我们拟按“先核实口径、再拆解任务、同步评估风险、形成闭环交付”的原则推进：
1. ...
2. ...
3. ...

需要同步请示/确认的事项：
1. ...

【对下任务安排】
1. 任务：...
   主责：...
   协同：...
   依据：...
   交付物：...
   时限：...
   验收标准：...

【风险与保障】
...
```

## 混合型模板

适用：材料里既有下属汇报，也有领导指示。

```text
【意图判定】
本事项属于“混合型”：其中...属于向我汇报，...属于需我推进。

【材料检视】
...

【对上响应】
...

【对下部署】
...

【需补证和待决策事项】
...
```

## 周报 / 月报 / 复盘模板

适用：用户要基于本周、本月、阶段性材料形成工作总结、管理复盘或向上汇报。

```text
【周期】
本报告覆盖：...

【总体判断】
本周期工作总体处于：按计划推进 / 有关键突破 / 存在明显偏差 / 需升级协调。

【关键进展】
1. 事项：
   目标：
   已完成：
   结果：
   依据：

【问题与风险】
1. ...

【需要协调】
1. ...

【下周期重点】
1. 任务：
   主责：
   协同：
   交付物：
   时限：
   验收标准：

【管理复盘】
1. 哪些动作有效：
2. 哪些问题反复出现：
3. 哪些事项应升级为机制：
```

## 产品方案专项检查

医疗健康服务产品：

- 服务对象是否清楚。
- 服务资源、履约能力、专家/机构/供应商是否可支撑。
- 服务流程、交付标准、质量控制是否明确。
- 涉及医疗、隐私、数据、宣传口径时是否需合规审核。

互联网化产品：

- 用户场景、入口、流程、数据指标是否清楚。
- 系统边界、研发归口、测试验收、上线节奏是否明确。
- 与现有平台、商城、问诊、家医、健康档案等能力是否匹配。

金融产品：

- 是否涉及保险、银行、理赔、权益、账户资金、委托消耗等口径。
- 是否明确适当性、合规、权益兑现、费用和风险披露。
- 不得承诺知识库或合规依据中没有支撑的收益、疗效或理赔结果。
